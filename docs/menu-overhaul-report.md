# Menu Overhaul — implementation report

Status: every out-of-run menu screen is rebuilt in the "Fog County" style and the full `tools/validate.sh` exits 0 (includes the new `tests/menus_regression.gd`, 66 checks, and the updated `tests/menu_systems.gd`, 55 checks).
**Not playtested by a human, never run on a real display or on Windows, controller input untested on hardware. Screenshots are software-rendered (Vulkan→llvmpipe) at 1920×1080.**

## 1. What was built
| Screen | Class / scene | Notes |
|---|---|---|
| Main menu | `MainMenu` | Logo, Play / Unlocks / Quests / Settings, silver, "Within reach" quest memos over the live world backdrop |
| Prepare your run | `LoadoutScreen` | Weapon / Trait / Ultimate slots with filterable dropdown, destination sign, personal bests |
| Unlocks (5 tabs) | `UnlocksScreen` | Weapons (4×2 tiles, memo with weapon preview, level-up option chips, weapon-slot purchase), Tomes, Traits, Items (rarity filter chips, 10×6 grid, memo with gem requirement / Unique stamp / drop weight / sources), Ultimates |
| Quests | `QuestsScreen` | Category tabs, memo-card grid, claim from mouse, keyboard or pad |
| Settings | `SettingsScreen` | Display / Graphics / Audio / Gameplay tabs, switches, sliders, steppers, key bindings, Quit game |

Shared: `MenuScreen` (shell, fade, key hints, Esc/Q/E), `FrameScreen` (title, silver, Home, tab bar), `MenuStyle`, `MenuData` (all derived menu data), widgets in `ui/menu/widgets/`. Old page-based menu code in `FrontEnd` was removed.
Single source of truth: names, costs, tiers, drop weights, requirements and unlock rules are read from `Catalog`, `ItemStats`, `MetaProgress` — none are typed into the screens.

## 2. Weapon preview — looping recording, not live
The Polaroid on Unlocks > Weapons plays a **looping pre-rendered sprite sheet** (`assets/ui/weapon_previews/<id>.png` + `previews.json`, ~6 MB), generated by `tools/weapon_preview_from_mockups.py` from the `W-*.dc.html` boards. It is not a live render of the weapon. Weapons without a board (Shotgun is locked in the demo profile) show the placeholder. Reduced-motion shows a still frame. The Aura loop has a visible seam.

## 3. Judgement calls and deviations from the mockups
- **Data wins over mockup**: item sources text comes from the drop rules (`ItemStats.DROPS`), not the mockup's fixed sentence; weapon descriptions are generated from weapon data; locked items still show their effect text.
- Tome/Trait icons are drawn at 64 px (whole-number 2× of the 32 px art); the mockup's 76 px would blur the pixel art.
- **NEW badge** is data-driven: existing profiles are migrated with every current entry marked seen, so nothing is "new" after an upgrade; only newly added entries show NEW. The mockup's NEW on Shotgun is therefore not reproduced.
- Quests and Settings have no mockups; they follow the kit (memo cards, dark rows). Quests are ordered claimable → active (by progress) → claimed. Settings use the kit's names for controls.
- The mockup files are unrendered templates (`{{sel.name}}`), so comparison is on layout, spacing and palette, not pixel diff (`docs/images/menus/compare-mockups.png`).
- Old test assertions updated because the icon source changed (weapon and tome icons are now individual 32×32 files under `assets/icons/`) and because Settings is tabbed (`milestones`, `dusk_update`, `retro_audio`).

## 4. Bugs found and fixed on the way
- The fog/vignette overlay was never added to menu screens (`add_child` was swallowed by a trailing comment); it also leaked at exit and failed validate.
- `MenuScreen` static variables and a static `Callable` that held the game left the engine with heap corruption at shutdown; state now lives in `Engine` metadata and a node group.
- Deferred focus on freed controls produced engine errors; replaced with `focus_later`.
- Buying an entry left its NEW badge; it is now marked seen.

## 5. Evidence
